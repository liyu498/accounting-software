# 代理记账桌面端改造设计规格

日期: 2026-06-22
项目: accounting-software-new-tauri
目标平台: macOS / Windows 桌面端, 浏览器预览仅用于开发调试

## 1. 目标

把现有 Tauri + React + Rust + SQLite 半成品扩展成一套可日常使用的代理记账多功能桌面软件。产品形态继续保持桌面端, Windows 必须作为一等支持平台, macOS 同步支持。

核心目标是覆盖代账业务主链路:

数据采集 -> AI 识别/分类 -> 自动匹配规则 -> 凭证草稿 -> 审核生成凭证 -> 账簿/报表 -> 期末结转/风险检查 -> 税务取数/申报工作台 -> Excel/PDF 导出打印。

## 2. 竞品观察结论

竞品采用外层账套壳加内层业务页面的结构。其核心价值不是单个页面, 而是围绕多企业、多账期、发票、银行、凭证、账簿、报表、税务申报形成闭环。

本项目可复刻的范围:

- 高度可复刻: 页面信息架构、表格字段、筛选项、工具栏、业务状态、账簿报表格式、Excel/PDF 导出版式。
- 产品级可替代: AI 发票识别、银行流水分类、自动凭证推荐、规则推荐、风险检查、税表差异解释。
- 需要外部接口后续接入: 税局真实申报、扣款、回执/缴款书收取、发票云票池、银行直连采集。

税局和银行相关能力先做成可审计的工作台和接口预留, 不在没有合法接口时伪装成真实自动提交。

## 3. 产品架构

### 3.1 桌面端架构

- 前端: React + TypeScript + Zustand + Tailwind。
- 桌面壳: Tauri 2。
- 后端命令: Rust Tauri commands。
- 本地数据库: SQLite。
- 文件能力: 本地附件、导入 Excel、导出 Excel/PDF、打印预览。
- 开发预览: Vite 浏览器模式可用, 但不替代真实桌面持久化。

### 3.2 Windows 支持

Windows 是目标交付平台之一。实现时需要:

- 避免 macOS 专属路径和文件操作假设。
- 导入/导出路径统一通过 Tauri dialog 或 Rust 文件命令。
- SQLite 数据目录使用 Tauri app data directory。
- 打包脚本保留 .exe / .msi 交付能力。
- Playwright/Vite 只作为开发验证, 不绑定最终桌面能力。

## 4. 信息架构

### 4.1 顶层

- 客户总览: 多企业进度看板、资料收集、账务进度、申报进度、缴款进度、漏报检查。
- AI 做账: 发票识别、流水分类、凭证推荐、风险提示、规则建议。
- 业务处理
- 财务
- 报表
- 税务申报
- 设置

### 4.2 业务处理

需要补齐:

- 销项发票
- 发票勾选
- 进项发票
- 银行账单/账单一览
- 票据
- 单据登记
- 账户转账
- 人员登记
- 薪酬表
- 社保公积金
- 专项附加扣除
- 折旧摊销
- 存货设置
- 计量单位

页面模式统一为: 查询区 + 操作工具栏 + 表格 + 状态/凭证/附件列 + 导入导出入口。

### 4.3 财务

需要保留并强化:

- 会计凭证: 新增、审核、反审核、打印、导出、复制、红冲、断号整理、批量删除。
- 期末结转: 增值税、附加税、印花税、折旧摊销、成本、所得税、往来调整、损益、本年利润。
- 风险检查: 只读检查、结账前校验、问题清单。
- 账簿: 科目余额表、科目汇总表、总账、明细账、辅助核算账、辅助余额表、多栏账。

### 4.4 报表

会计报表:

- 资产负债表
- 利润表
- 利润表季报
- 现金流量表
- 现金流量表季报
- 所有者权益变动表

税务报表:

- 增值税及附加
- 扣缴所得税
- 印花税
- 企业所得税
- 社保费
- 财报报送

报表页需要支持重新计算、刷新、导出、打印、公式/取数说明、重分类设置。

### 4.5 税务申报

实现为申报工作台, 不直接承诺真实税局提交。

状态流:

未取数 -> 已取数 -> 校验通过/失败 -> 待确认 -> 已申报 -> 扣款状态 -> 回执/缴款书。

每个动作必须有:

- 二次确认
- 操作日志
- 取数快照
- 错误和风险说明
- 可回溯来源凭证/报表

真实申报、扣款、回执收取作为 adapter 接口预留。

### 4.6 设置

需要对齐竞品:

- 企业信息
- 期初余额
- 申报初始化
- 历史凭证
- 历史科目余额表
- 历史总账
- 历史明细账
- 账户登记
- 客户
- 供应商
- 其他往来
- 项目
- 部门
- 标签
- 科目设置
- 资产类别
- 账单自动匹配规则
- 发票自动匹配规则
- 会计凭证回收箱

客户、供应商、其他往来共享同一套辅助资料表格组件, 字段包括编码、名称、简称、助记码、地址、电话、开户银行、银行账号、税号、外币核算、别名、状态。

## 6. AI 做账设计

AI 不做黑箱记账, 只产生可解释建议。

能力:

- 发票 OCR/结构化识别。
- 发票商品、税率、客户/供应商匹配。
- 银行流水摘要和对方户名分类。
- 单据和附件识别。
- 自动凭证草稿生成。
- 重复票据/异常金额/税率异常提示。
- 自动匹配规则推荐。
- 税表取数差异解释。

AI 结果状态:

待识别 -> 已识别 -> 待确认 -> 已采纳/已拒绝 -> 已生成凭证。

凭证生成前必须展示:

- 来源单据
- 借贷分录
- 科目和辅助核算
- 金额税额
- 置信度
- 风险提示

## 7. 导出和打印

统一做 export/print engine, 避免每页手写一套导出。

格式:

- Excel: 表头合并、金额列格式、冻结首列/表头、汇总行。
- PDF: 凭证、账簿、报表使用固定模板。
- 打印: 凭证纸、A4、A5、B5 等规格预留。

优先模板:

- 会计凭证
- 科目余额表
- 明细账
- 总账
- 资产负债表
- 利润表
- 现金流量表
- 所有者权益变动表
- 发票清单
- 银行账单
- 薪酬表
- 折旧明细表
- 申报表清单

## 8. UI 原则

这是代账操作软件, 不是营销站。

- 高密度但清晰。
- 左侧分组导航 + 顶部账期/企业/状态。
- 页面内使用查询区、工具栏、表格、抽屉/弹窗。
- 不用大面积宣传卡片和装饰性渐变。
- 表格需要列显隐、分页、横向滚动、状态标签、批量选择。
- 关键危险动作使用二次确认。
- 已结账期间禁止或限制变更, 允许只读查看和导出。

- 业务处理完整模块。

- AI 做账流程。

## 10. 分阶段实施

### 阶段一: 信息架构和页面骨架

补齐路由、导航、页面模板、统一表格/筛选/工具栏组件。先用本地 mock 数据验证交互和版式。

### 阶段二: 核心业务闭环

发票、银行、单据、凭证、账簿、报表、期末结转串起来。SQLite schema 和 Rust commands 同步扩展。

### 阶段三: AI 做账

实现 AI job、识别结果、凭证建议、置信度、人工确认、审计日志。

### 阶段四: 税务申报工作台

实现申报表、状态流、取数快照、校验、确认、日志、导出。真实税局 adapter 预留。

### 阶段五: 导出/打印和 Windows 打包

完成 Excel/PDF 模板、打印预览、Windows 打包验证。

## 11. 验收标准

- Windows 和 macOS 均可运行桌面端。
- 浏览器预览不报错, 但明确区分 mock 和真实桌面能力。
- 每个核心模块可打开、筛选、分页、导入/导出入口明确。
- 凭证、账簿、报表之间数据来源可追踪。
- AI 生成凭证前必须人工确认。
- 申报和扣款类动作默认不可静默执行。
- 关键表格和 PDF/Excel 模板接近竞品字段和版式。
- npm run build 通过。
- 涉及 Rust/SQLite 时 cargo check 通过。

## 12. 当前约束

- 不复制竞品私有代码和接口。
- 不记录或复用竞品页面里出现的真实客户敏感数据。
- 税局、银行、发票平台能力需要合法接口后才能实现真实自动化。
- 当前设计先以本地桌面端、可审计流程、接口预留为主。
