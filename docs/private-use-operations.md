# 私人使用数据安全与备份基线

本项目按单机桌面软件运行，面向私人管理多家客户账套。它不提供多台电脑实时协同或云端集中数据库。

## 数据保护

- 应用数据库和备份位于当前系统用户的应用数据目录；macOS/Linux 会把目录权限收紧为 `0700`、文件权限收紧为 `0600`。
- 管理员密码使用 bcrypt 哈希保存。税务、银行、票池和 OCR 适配器只保存环境变量名称，不保存外部平台密钥。
- 使用前必须为系统磁盘启用 FileVault（macOS）或 BitLocker/设备加密（Windows）。应用层 SQLite 当前不提供独立静态加密。
- 不要把应用数据目录、数据库、备份或导出文件放在多人共享目录。复制到移动硬盘或网盘时，应使用加密卷或端到端加密空间。
- 每位本机使用者应使用独立系统账户；不要共享管理员密码。

## 自动与手工备份

- 桌面端启动时检查自动备份；距离最近一次自动备份满 24 小时才创建新快照。
- 自动快照最多保留 30 份，只清理 `automatic-*.db`；手工快照和恢复前安全快照不参与自动清理。
- 自动维护动作写入操作审计日志。所有快照使用 SQLite `VACUUM INTO` 创建，并可执行文件头与 `PRAGMA quick_check` 完整性校验。
- 批量导入、期初初始化、结账、跨年和大规模调整前，仍应在“备份恢复”页面执行一次手工备份。

建议运维节奏：

| 周期 | 操作 |
| --- | --- |
| 每次启动 | 确认最近自动快照存在且没有备份错误 |
| 每周 | 校验最新手工快照后，使用“导出副本”保存到加密的异机介质 |
| 每月 | 校验至少一份自动快照和一份异机快照 |
| 每季度 | 在非生产副本上完成一次恢复演练 |
| 年末结账前 | 创建并校验手工快照，另存一份加密异机副本 |

## 多客户和账期隔离

- 每个客户必须建立独立账套，不得通过修改企业名称复用旧账套。
- 账户档案、发票、流水、凭证、报表、申报任务和附件均以 `company_id` 作为账套边界。
- 会计账期拥有独立 ID；同一年月在不同客户账套中不是同一个账期。凭证创建会同时校验账套和账期归属。
- 停用客户账套前先完成手工备份；永久删除只用于已确认不再保留的数据。
- 发布门禁 `npm run verify:release-isolation` 会验证两家客户的账户资料、全年账期、发票和凭证不能跨账套读取或写入。

## 恢复处理

1. 在“备份恢复”页面先执行完整性校验。
2. 安排恢复时，系统会先自动创建恢复前安全快照。
3. 完全退出并重新打开应用；数据库连接建立前才会替换目标快照。
4. 恢复后核对客户数量、当前账期、期末余额、最近凭证和审计日志。
5. 损坏快照会被隔离，不会覆盖当前数据库。

不要直接覆盖 `accounting.db`，也不要在应用运行时复制数据库文件作为备份。

## 本地验收命令

```bash
npm test
npm run verify:release-acceptance
npm run verify:release-isolation
npm run verify:release-recovery
npm run verify:release-performance
```

上述门禁通过后，仍需用实际脱敏账套核对期初余额、账户档案、不同账期凭证、总账、明细账和法定报表。
